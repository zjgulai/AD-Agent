# 红人素材广告加推 Agent Loop · 角色·触点·链路全景

## 核心问题

品牌如何把红人（达人）内容里被验证的优质素材，自动化地转化为可规模化投放的广告资产？这套「红人素材广告加推 Agent Loop」的角色分工、系统触点、Agent 编排和人工确认（HITL）节点是怎样的？

## 系统解答

### 1. 业务定位

自动识别高潜力红人内容 → 完成授权合规 → 生成多平台加推策略 → 创建广告并上线 → 持续监控优化 → 复盘沉淀，形成「发现→授权→策略→投放→监控→优化→复盘→反哺」的闭环。覆盖平台：TikTok、Instagram（Meta）、YouTube（Google）。

### 2. 用户角色（3 个）

| 角色 | 职责 | 关键决策点 | 主要系统 |
|------|------|-----------|---------|
| 红人推广负责人 | 管理红人内容池与资源，判断素材价值，索要/登记视频授权，关注广告表现 | 确认/拒绝加推、发起授权索要、登记授权码、查看复盘、问询效果 | 红人系统 + 飞书 IM |
| 广告负责人 | 管理投放策略、预算、上线与优化 | 确认策略、确认投放、确认优化建议、处理上线检查异常、看日报/复盘 | 广告系统 + 飞书 IM + 三方广告平台 |
| 红人 | 外部内容创作者，提供视频授权 | 接收授权邀约、提供授权码 | 邮件/外部 IM |

> 红人为外部协作角色；红人推广负责人同时承担红人资源管理与内容加推决策。

### 3. 交互触点（5 个系统 + 飞书 IM 贯穿）

- **飞书 IM**：Agent 的「嘴」——所有通知、HITL 确认、主动问询、日报/周报、授权索要都走 IM 卡片。
- **红人系统**（Web）：内容池浏览、AI 潜力标签/评分、授权状态管理、加推确认。
- **广告系统**（Web）：策略查看/编辑、批量操作、异常列表、跳转三方平台。
- **三方广告平台**（TikTok Ads / Meta Ads / Google Ads 后台）：真实投放落地。
- **邮件/外部 IM**：向红人发授权邀约、回收授权码。

跳转设计四原则：IM 消息永远带跳转链接；系统内跳转带上下文自动定位；跨系统有回退路径；平台标识贯穿全程。

### 4. Agent 编排（按平台拆分后共 13 个）

**内容发现与评分层（平台无关）**

- ① 素材发现 Agent：定时扫描三平台内容池 → 规则过滤 + AI 内容理解 → 初筛
- ② 潜力评分 Agent：6 维度加权评分（内容质量 20% / 自然互动 15% / 产品匹配 20% / 人群匹配 15% / 历史表现 20% / 品牌安全 10%）→ Ad Potential Score + 等级（强烈推荐/推荐测试/观察/不推荐）+ 推荐平台

**策略与创建层（按平台拆分 ×3）**

- ④-T/M/Y 加推策略 Agent：生成各平台 Ad Boost Plan（受众、版位、预算、测试方案）；信息缺失时经 IM 向广告负责人补齐
- ⑤ 素材组装 Agent：**暂不建设**，直接使用红人原视频授权加推（Demo 中灰显标注"下一阶段建设"）
- ⑥-T/M/Y 广告创建 Agent：生成 Campaign/Ad Set/Ad 结构 → 先过 ⑦ 上线检查 → 调平台 API 建草稿（TikTok Ads API / Meta Marketing API / Google Ads API）

**监控分析与优化层（统一汇总）**

- ⑦ 上线检查 Agent：统一引擎 + 平台差异化规则，7 项通用检查（授权/UTM/追踪/命名/预算阈值/品牌安全/禁用词）+ 各平台专项；被创建 Agent 调用，被阻断时 IM 通知修改后重检
- ⑧ 广告监控 Agent：每小时扫全量广告（不限加推），异常判定（消耗突增/CTR 骤降/ROAS 跌破阈值/零花费/花费过快），阈值按平台独立配置
- ⑨ 广告效果分析 Agent：日报 + IM 主动问询；四维分析（素材/红人/平台/Campaign），核心是「解释原因」而非只报数据
- ⑩ 广告优化 Agent：五维优化（预算/受众/创意/出价/Campaign），**三级自动化**——L1 只建议 / L2 执行前人工确认 / L3 低风险自动执行后 IM 通知
- ⑬ 红人素材广告复盘 Agent：日/周报 + 批次复盘，跨平台汇总 ROAS/CPA/CTR 对比，反哺下一轮素材发现，闭环 Loop

### 5. HITL 节点（3 个人工确认点）

| 节点 | 触发 | 决策者 | 动作 |
|------|------|--------|------|
| ②.5 授权索要 | 高评分素材未授权 | 红人推广负责人发起，红人提供授权码 | IM/邮件邀约 → 授权码登记（人工或 Agent 自动识别） |
| ③ 运营确认加推 | 授权完成进入待确认池 | 红人推广负责人 | 批量确认/观察/拒绝 → 通知广告负责人 |
| ④ 策略确认 + 投放开启 | 策略生成、草稿创建 | 广告负责人 | 按平台批量确认策略、手动开启正式投放 |

### 6. 完整 Loop 链路

素材发现(①②) → 授权 HITL(②.5) → 加推确认 HITL(③) → 三平台策略(④) → [素材组装⑤跳过] → 三平台创建+上线检查(⑥⑦) → 手动投放 → 监控告警(⑧) → 效果分析(⑨) → 优化执行(⑩) → 日/周复盘(⑬) → 反哺素材发现，Loop 闭环。

## 高频问答索引

- **Q：这套 Loop 覆盖哪些广告平台？平台差异怎么处理？**
  A：TikTok、Instagram（Meta）、YouTube（Google）。策略、创建、监控、优化按平台拆分独立 Agent 或独立规则；上线检查用统一引擎 + 平台差异化规则；监控阈值按平台独立配置。
- **Q：Agent 会不会自动改广告？人工把关在哪？**
  A：优化 Agent 分三级自动化：L1 仅建议、L2 执行前 IM 审批、L3 低风险动作（如低效素材降预算 10%）自动执行后通知。另有 3 个人工确认节点：授权索要、加推确认、策略/投放确认。
- **Q：素材没授权能投放吗？授权流程怎么走？**
  A：不能。高评分素材自动检查授权状态，未授权进入授权索要 HITL：IM/邮件向红人发邀约 → 红人回复授权码 → 负责人在红人系统登记授权码+有效期（或 Agent 自动识别登记）→ 授权完成才进待确认加推池。
- **Q：素材组装 Agent（⑤）为什么没有？**
  A：明确暂不建设，直接用红人原视频授权加推；Demo 中灰显标注"下一阶段建设"。[来源：S2]
- **Q：监控和分析是只看加推广告吗？**
  A：不是。⑧监控和⑨分析覆盖**全量广告**（三平台汇总+分平台对比），不只限于红人加推。
- **Q：上线检查具体查什么？**
  A：通用 7 项（素材授权/UTM 规范/追踪配置/命名规则/预算阈值/品牌安全/禁用词）+ 平台专项（TikTok Spark Ads 授权码与时长、Meta 版权/Reels/Pixel 事件、YouTube TrueView/Google Ads 关联/频道关联）。不通过则阻断创建并 IM 通知修改重检。
- **Q：潜力评分怎么算？**
  A：6 维加权——内容质量 20%、自然互动 15%、产品匹配 20%、人群匹配 15%、历史表现 20%、品牌安全 10%，输出分数+等级+推荐平台。
- **Q：复盘结果怎么用？**
  A：⑬复盘 Agent 输出日/周报（红人内容数据+广告数据+平台对比+结论+下一步建议），同时推给广告负责人和红人推广负责人；结论反哺下一轮素材发现，形成 Loop 闭环。
- **Q：用户主要在哪些系统操作？**
  A：飞书 IM 是交互主入口（通知/确认/问询）；红人系统管内容池与授权；广告系统管策略、草稿、异常、优化建议；三方平台后台是最终投放地。
- **Q：信息不全时策略 Agent 怎么办？**
  A：缺目标国家、预算上限、平台素材格式等关键信息时，经飞书 IM 主动向广告负责人问询，补齐后继续生成策略。
