# Meta 广告诊断与优化 SOP · G0–G8 固定顺序与 65 节点诊断引擎

## 核心问题

Meta 广告（Facebook/Instagram/AN）出现花费、CPA、ROAS、CTR 等异常时，如何按固定顺序定位根因并安全处置？这套「Meta 广告诊断与优化 SOP」的检查顺序、P0/P1/P2 优先级、动作铁律，以及 65 节点 / 196 分支诊断执行台的结构是怎样的？

## 系统解答

### 1. 业务定位与输入输出

- 面向 **AI Agent、投放新人和投放专家**；所有阈值均可后台配置。
- 适用平台：Meta 广告（Facebook/Instagram/AN）；可扩展至 TikTok/Google，但需重新校准阈值。
- 适用目标：销售、引流、线索、应用安装、互动、视频观看、消息、目录销售；**销售/DTC 为主**。
- 输入：广告系列、广告组、广告创意、漏斗事件、账户配置、业务状态；**原始数据与计算区分开**；「三层+漏斗」口径。
- 输出：**异常 → 证据 → 根因 → 动作 → 影响预估**，每次诊断必须五段式输出。
- 固定顺序：G0 数据可信度 → G1 资格 → G2 追踪归因 → G3 目标事件 → G4 样本 → G5 预算 → G6 专项 → G7 分层 → G8 安全 → 复核；**不得跳过前置检查**；动作后 4h/24h/72h 复核。

### 2. G0–G8 固定检查顺序

| 阶段 | 检查什么 | 判定标准（异常出口） | 异常分支去向 | 正常下游 |
|------|----------|----------------------|--------------|----------|
| G0 数据可信度 | 报表延迟、公式差异、事件质量、订单差异、页面可达（进入条件：报表已同步） | 数据错误/追踪异常 | **冻结普通优化** | G1 资格 |
| G1 资格与账户 | 账户限制、拒登、支付、Learning、账户结构、预算集中 | 账户/页面/支付异常 | **P0 修复** | G2 追踪归因 |
| G2 追踪归因 | 事件质量、重复事件、延迟、后台订单与 Ads 订单差异 | EQ<4 或差异>30% | **停止策略诊断** | G3 目标事件 |
| G3 目标事件 | 目标类型、优化事件、周转化量、Learning 状态 | 目标事件错误 | **修正后重新学习** | G4 样本 |
| G4 样本 | 曝光、花费、点击、LPV、ATC、IC、Purchase | 样本不足 | **仅监控并预约复测** | G5 预算 |
| G5 预算 | Pacing、预算完成率、出价达成率、ROAS/CPA | 欠投/超投 | **走预算分支并结束本轮** | G6 专项 |
| G6 专项 | 按曝光、引流、销售、重定向选择指标链路（曝光、CTR、CPM、LPV、漏斗、CVR、CPA、ROAS、频次） | 命中专项异常 | **执行对应动作** | G7 分层归因 |
| G7 分层 | 国家、设备、版位、人群、素材、页面、商品根因（分层花费、CTR、CVR、CPA、ROAS、重叠、疲劳） | — | **确认主因后只执行一个主动作** | G8 动作安全 |
| G8 安全 | 近 12 小时人工变更、大促窗口、单变量、冷却期、回滚条件 | 不满足安全条件 | **只告警，不自动执行** | 执行动作 → 12h/24h/72h 复核 |
| 复核 | 花费、曝光、CTR、LPV、CVR、CPA、ROAS、数据延迟 | 达到回滚条件 | **回滚并升级** | 完成闭环，写入动作日志 |

> 数据质量提示：sheet-01 G8 行写「12h/24h/72h复核」，但同表 P4.2 节点、sheet-00 与 sheet-04 均为 **4h/24h/72h**，「12h」疑为笔误 `[待确认]`。

### 3. 优先级体系

| 优先级 | 定义 | 约束 |
|--------|------|------|
| P0 立即止血 | 最严重异常（如 ROAS 亏损、落地页不可达、数据不可信） | **P0 冻结普通优化动作** |
| P1 当日干预 | 当日需处理的异常 | — |
| P2 计划内优化 | 可排期处理的预警/观察项 | — |

> 注意：节点编号前缀 `P0-01` 指「前置检查阶段第一个节点」，分支上的「优先级 P0」指「止血级」，两者是不同字段，不能混用 [来源：S5]。

### 4. 动作铁律与数据成熟度

- **一次只动一个主变量**：不得同时改预算、出价、素材和人群。
- **学习期不判效**：学习期内不出效果结论，相应动作待学习期结束后复核。
- **动作后必须复核**：4h / 24h / 72h 三个时点回填，缺复核视为未闭环。
- **冷却期 24h～72h**：同一对象同类动作在冷却期内不重复下发。
- **归因成熟度 ≥80%**：归因窗口成熟度未达 80% 时仅预警，**禁止正常判断 CPA/ROAS**。
- S5 PRD 进一步落地为 6 条硬约束 + 「动作优先级排他矩阵」（暂停广告 > 缩减预算 > 刷新素材 > 调整出价，多分支同命中时只保留一个主动作）+ 两道保护期前置闸门（新建对象冷启动 24h、归因延迟缓冲期）[来源：S5]。

### 5. 诊断引擎结构：65 节点 / 196 分支

sheet-01「总览诊断执行台」把 G0–G8 展开为可执行的节点级决策表（表名标注「需业务确认」`[待确认]`）。

**层级组织（65 节点）**

| 阶段分组 | 节点 ID 范围 | 节点数 | 覆盖检查阶段 | 下钻层级 |
|----------|--------------|--------|--------------|----------|
| 前置检查 | P0.1–P0.5（诊断 ID P0-01~P0-05） | 5 | G0–G4 前置闸门 | L0/L1/L4 |
| 广告系列整体诊断 | S1.1–S1.13 及下钻子节点 S1.2a/S1.2b/S1.2b-1/S1.2b-2/S1.3a/S1.3b/S1.3c/S1.4a/S1.4b/S1.5a/S1.5b/S1.12a/S1.12b/S1.12c | 27 | G5 预算 + G6 系列级专项 + G7 初步归因 | L1 |
| 广告组整体诊断 | S2.1–S2.16 | 16 | G6/G7 广告组级专项与横向对比 | L2 |
| 广告创意整体诊断 | S3.1–S3.15 | 15 | G6/G7 创意级专项（视频质量、素材疲劳、漏斗） | L3 |
| 后置检查 | P4.1 动作安全检查、P4.2 动作后复核与回滚 | 2 | G8 安全 + 复核闭环 | 全局 |

合计 5+27+16+15+2 = **65 节点**；每节点约 3 条 IF 分支，共 **196 行分支**（S5 PRD 口径一致）。

**节点命名规律（三层 ID）**

- **阶段节点 ID**：`P0.1` / `S1.4a` / `S2.15` / `P4.2`——点号小数表示主节点与归因下钻子节点（如 S1.2b-1 按出价策略再分流）。
- **诊断 ID**：`P0-01` / `S1-04a` / `S2-15`——连字符形式，供动作日志「诊断ID」字段引用。
- **IF 分支 ID**：`S1-04a-B01`——每个分支一行，B01/B02/B03 对应「异常/预警/正常」三档；个别节点有变体（S1.3a 按出价策略拆为 B01a/B01b 四分支）。

**每行分支的字段结构（27 列）**：阶段、阶段节点 ID、决策路径类型、下钻层级（L0–L4/全局）、诊断 ID、诊断名称、诊断目的、诊断类型、诊断数据源、诊断指标、IF 分支 ID、IF 条件、诊断结论、推荐动作类型、动作改动明细、预期影响、动作优先级、再次巡检重点、关键项备注、指向下游环节、数据记录、异常处理、结果判定、阈值依据、终止本轮、后续交接、前置准备。每行自带完整「诊断→动作→复核→下游」闭环，无需跨行拼接。

**分支逻辑**

- 主流模式为**三档判定**：B01=异常（P0/P1，给动作）、B02=预警（P1/P2，多为「持续观察/储备」）、B03=正常（「进入下游」）。「终止本轮」列在正常分支为「是」、异常/预警分支为「否」`[推断：语义为本轮异常处置是否终止]`。
- 「决策路径类型」列修正说明称可取 前置/路由/兜底，但 196 行实际值全部为「诊断」`[待确认]`。
- 「诊断类型」共 23 种标签：全局配置型、资格型、兜底验证型、配置健壮型、质量控制型、资金节奏型、流量获取型、竞价型、成本型、素材型、人群型、大盘型、漏斗型、转化型、盈利型、样本量型、分层效率型、触达疲劳型、视频质量型、内容衔接型、技术链路型、安全控制型、闭环复核型。

**代表性决策路径（每阶段最重要分支）**

- **前置检查 P0-01 归因口径校准**（G0/G2）：`EQ<4 或订单差异率>30%` → 数据可信度异常、诊断结果不可信 → 数据修复（修 Pixel/CAPI 事件去重、核对 Purchase 参数）→ P0，48h 复测；`EQ 4~6 或差异率 20%~30%` → 预警持续观察；`EQ≥6 且差异率≤20%` → 进入 P0.2。归因窗口不一致时统一后等 48h。
- **系列级 S1-13 ROAS 诊断**（G6 盈利收口）：`ROAS<盈亏平衡×0.7` → P0 止血/归因（暂停系列→查 CPA/客单价/归因口径）→ 阶段2 广告组诊断；盈亏平衡=1÷毛利率。
- **系列级 S1-02b 排名丢失归因**（G6 竞价分流示例）：因排名丢失>20% 时按出价策略分流——Cost Cap/Bid Cap 看 CPM 比值（<0.85 提价 10%~15%），Lowest Cost 禁止提价、转 S1.4 CTR 素材归因。
- **后置 P4-02 动作后复核**（复核闭环）：`CPA+≥20% 或 ROAS-≥20% 或数据延迟>6h` → P0 回滚最近动作并重新进入前置检查；`CPA+10%~20% 或 ROAS-10%~20%` → P1 密切监控、禁止追加动作；达标 → 诊断闭环写入动作日志。

**与 S5 PRD 的关系**：S4 策略树是规则资产源表，S5 将其产品化为「规则引擎负责判断（65 节点/196 分支/25 项基准线可配置）、LLM 只负责理解/表达/沉淀」的架构；S5 新增保护期闸门、动作优先级排他矩阵、三档执行权限与熔断器，均不改变策略树本身 [来源：S5]。已知差异：S5 流程图 3 的 G0–G8 命名（G1 学习期判定/G2 异常确认/…/G8 执行权限路由）与 S4 表格口径（G1 资格/G2 追踪归因/…/G8 安全）不一致，S5 正文表格与 S4 一致，疑为图示简化 `[待确认]`。

## 高频问答索引

- **Q：诊断必须按什么顺序执行？能跳过前置检查吗？**
  A：不能。固定顺序 G0 数据可信度 → G1 资格 → G2 追踪归因 → G3 目标事件 → G4 样本 → G5 预算 → G6 专项 → G7 分层 → G8 安全 → 复核，任一阶段命中异常出口即在该阶段收口，不进入下一阶段。
- **Q：P0、P1、P2 怎么分？P0 会冻结什么？**
  A：P0 立即止血（如 ROAS<盈亏平衡×0.7、落地页不可达、EQ<4）、P1 当日干预、P2 计划内优化。P0 冻结普通优化动作，只允许止血/修复类动作。
- **Q：动作铁律具体有哪些？**
  A：一次只动一个主变量（不得同时改预算、出价、素材、人群）；学习期不判效；动作后必须 4h/24h/72h 复核；冷却期 24h～72h；归因窗口成熟度 ≥80% 才允许正常判断 CPA/ROAS，未成熟仅预警。
- **Q：65 节点 / 196 分支怎么组织？**
  A：五段式——前置检查 5 节点（P0.1–P0.5，对应 G0–G4）+ 广告系列级 27 节点（S1，对应 G5/G6 系列专项）+ 广告组级 16 节点（S2）+ 广告创意级 15 节点（S3）+ 后置检查 2 节点（P4.1 安全、P4.2 复核）。每节点约 3 条 IF 分支（异常/预警/正常三档），每行 27 列自带完整处置闭环。
- **Q：诊断输出是什么格式？**
  A：五段式——异常 → 证据 → 根因 → 动作 → 影响预估。节点行内已拆为诊断结论、推荐动作类型、动作改动明细、预期影响、动作优先级、再次巡检重点六个字段。
- **Q：数据不可信时会发生什么？**
  A：G0–G2 的异常出口直接收口：数据错误/追踪异常→冻结普通优化；EQ<4 或订单差异>30%→停止策略诊断；账户/页面/支付异常→P0 修复。先修归因口径再谈优化（对应动作 A-16）。
- **Q：多个分支同时命中怎么办？**
  A：铁律是「一次诊断只出一个主动作」。S5 落地为动作优先级排他矩阵：暂停广告 > 缩减预算 > 刷新素材 > 调整出价，冲突时只保留最高等级主动作，其余降为降级建议。
- **Q：样本不足能诊断吗？**
  A：不能做正式诊断。P0-05 数据充分性门槛：花费<$50 且 Purchase<30 → 仅延长观察；$50~100 或 Purchase 30~50 → 标低置信度、7 天后复测；≥$100 且 ≥50 → 进入正式诊断。广告组级另有 S2-01 门槛（≥$100 且转化≥30）。
- **Q：G5 预算异常为什么「结束本轮」？**
  A：欠投/超投走预算分支并结束本轮——预算节奏异常优先处置，避免在错误流量成本下做下游归因。
- **Q：这套 SOP 适用范围是什么？**
  A：Meta 广告（Facebook/Instagram/AN）为主，可扩展 TikTok/Google 但需重新校准阈值；目标以销售/DTC 为主，兼容引流、线索、应用安装等 8 类目标；阈值均可后台配置，需按国家、目标、版位、设备、新客/重定向、行业和季节校准。
