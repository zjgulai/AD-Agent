# Meta 广告诊断优化 SOP · Agent 训练版 · T0–T5 主决策树与 L0–L4 五层结构

## 核心问题

S7《【业务提供】Meta广告诊断优化SOP_Agent训练版_v7》是什么？它和 S4《Meta广告AI自动诊断与优化_完整策略树》是什么关系？这套「业务提供」的 Agent 训练版 SOP 用什么决策树组织诊断、五层（L0–L4）各管什么、阈值口径与 S4 有何差异？

## 系统解答

### 1. 文档定位与输入输出

- **定位**：面向 **AI Agent 训练 + 投放人员流程规范** 的双用途 SOP（sheet-00 声明）。与 S4「产品整理」策略树是**两套不同表述、同一主题**：S7 按「L0–L4 五层 + T0–T5 顺序树」组织，S4 按「G0–G8 阶段 + 65 节点/196 分支执行台」组织（详见第 4 节对照）。
- **输入**：广告账户数据（三层 Campaign/AdSet/Ad + 漏斗事件）与账户配置。
- **输出**：五段式诊断结论 **异常 → 证据 → 根因 → 动作 → 影响预估**（与 S4 输出口径一致）。
- **11 个页签结构**：00 文档说明 → 01 T0–T5 主决策树（24 节点）→ 02~06 五层诊断 SOP（28 个诊断项）→ 07 异常动作速查 → 08 动作库与影响预估 → 09 动作日志模板 → 10 字段字典与阈值。
- **五层诊断项统一 6 字段规程**：①前置准备（工具/校准/环境/资质）②详细步骤（编号·操作|判定|要领）③数据记录（参数/单位/格式）④异常处理（问题→处理）⑤结果判定（正常/异常·阈值）⑥后续动作与交接。压缩明细见 [meta-diagnosis-layers-l0-l4.md](./meta-diagnosis-layers-l0-l4.md)。

### 2. T0–T5 主决策树（sheet-01 全表，最高价值内容）

**入口规则**：任意「广告效果差」症状 → 按 T0 排雷 → 逐层下钻至根因 → 出口动作（A-xx）。**T0~T5 顺序执行，命中 THEN 即处理并回看，未命中进入 ELSE/下一层**。

**树的结构特征**

- **三段式组织**：T0 前置排雷（数据/账户/落地页可达，任一 P0 即停）→ T1 Campaign 健康度（结构、学习、Pacing、扩缩量决策）→ T2 症状路由（按 CTR/离散度/归因把异常导向 L0/L2/L3/L4）→ T3 L2 受众 → T4 L3 素材 → T5 L4 六层漏斗逐层穿透 + 归因兜底收尾。
- **与层级 SOP 的关系**：T3.x/T4.x/T5.x 是决策树节点，L2/L3/L4 sheet 是对应层的详细作业规程——树给「往哪走、做什么动作」，SOP 给「每一步怎么操作、怎么判定」。
- **动作编号问题**：树中出口标注 `A-xx`（A-03/A-04/05/A-07/A-08/A-13/A-14/A-15），但 sheet-08 动作库**无编号列**，且这些编号与 S4 的 A-01~A-16 体系无法逐一对应 `[待确认]`（详见第 4 节）。

### 4. 与 S4 策略树的对照

**组织方式**

| 维度 | S7（Agent 训练版 v7，业务提供） | S4（完整策略树，产品整理） |
|------|--------------------------------|---------------------------|
| 主干结构 | T0–T5 顺序决策树（24 节点）+ L0–L4 五层 SOP | G0–G8 九阶段闸门 + 65 节点/196 分支执行台 |
| 遍历方式 | 任意「广告效果差」症状入口，命中 THEN 即处理并回看 | 固定顺序 G0→…→G8→复核，不得跳过前置检查 |
| 节点粒度 | 树节点=路由/判定点；层内 28 个诊断项各带 6 字段规程 | 节点级 IF 分支三档判定（异常/预警/正常），每行 27 列自带闭环 |
| 优先级 | P0/P1/P2 散见于 THEN 与速查表，无独立定义节 | P0 立即止血/P1 当日干预/P2 计划内优化，P0 冻结普通优化 |
| 动作体系 | sheet-08 动作库 18 行**无编号、无回滚条件列** | sheet-03 动作库 A-01~A-16，带编号+回滚条件 |
| 日志 | sheet-09 10 列简化模板（72h 回填实际结果） | sheet-04 21 列模板（4h/24h/72h 三段复核+回滚条件+状态） |
| 服务对象 | 训练 AI Agent + 规范投放人员 | AI Agent、投放新人和投放专家（阈值可后台配置） |

**覆盖范围差异**

- S7 L0 显式拆出「账户结构健康」「像素与事件部署」「政策合规与账户安全」三个独立诊断项；S4 将账户资格、归因、事件质量折叠进 G0–G2 前置闸门与 G1 资格（P0-01~P0-05 五节点）。
- S7 L4 六层漏斗每层有独立 SOP；S4 漏斗由 G6 专项/G7 分层节点承载（S1.7~S1.10、S2.9~S2.13、S3.9~S3.12）。
- S7 独有：异常动作速查表（24 种现象→层级→根因→一句话动作）、字段字典含跳出率/ATC率/IC率等站内指标。
- S4 独有：节点级三档分支判定、动作铁律（一次只动一个主变量/学习期不判效/冷却期 24h~72h/归因成熟度≥80%）、21 列日志、动作后 4h/24h/72h 分档复核判定。S7 sheet-09 提到「铁律6：动作必留痕」，暗示存在铁律清单但未在导出页签中 `[待确认]`。
- S7 动作库 18 行中含 S4 没有的「降低出价目标」「调整落地页广告一致性」两项；按行序语义对应 S4 A-01~A-16（S7 第 9、17 行为新增）`[推断]`。

## 高频问答索引

- **Q：S7 是什么文档？和 S4 什么关系？**
  A：S7 是《Meta广告诊断优化SOP_Agent训练版_v7》，业务提供的双用途 SOP——训练 AI Agent 掌握诊断决策逻辑 + 规范投放人员流程。S4 是「产品整理」的完整策略树。两者同主题不同组织：S7 用 T0–T5 决策树+L0–L4 五层规程，S4 用 G0–G8 阶段+65 节点/196 分支；S5 PRD 是在 S4 之上做的产品化。
- **Q：诊断从哪里开始？T0–T5 怎么走？**
  A：任意「广告效果差」症状入口，先过 T0 前置排雷（EQ/归因差异、账户受限、落地页可达，命中即 P0 停止层内诊断），再 T1 查 Campaign（结构/Learning/Pacing/ROAS），T2 按症状路由到 L0/L2/L3/L4，T3 查受众、T4 查素材、T5 逐层穿透六层漏斗并归因兜底。命中 THEN 即处理并回看，未命中进 ELSE/下一层。
- **Q：T2.x 症状路由是干什么的？**
  A：把「异常 Campaign」按症状分流：CTR<0.5%（素材普遍低）→L3 素材诊断；CTR 正常但 CVR<1%→L4 漏斗；某 AdSet CPA 2x+ 均值→交叉验证后去 L2 受众或 L0；后台有单但归因少/ROAS 崩但转化量正常→L0-01/02 归因修复。
- **Q：L0–L4 五层各管什么？先查哪层？**
  A：L0 账户健康（归因/事件质量/结构/像素/预算资金/合规，6 项）→ L1 Campaign（Pacing/出价/学习/CBO/频控/整体效能，6 项）→ L2 AdSet（受众效率/规模/LAL/重叠/版位频次，5 项）→ L3 素材（CTR/视频/疲劳/文案CTA/CAT，5 项）→ L4 落地页六层漏斗（6 项）。顺序即 T0→T5 下钻路径；L0 是所有诊断的前置排雷。
- **Q：数据不可信或归因差怎么办？**
  A：T0.1/T2.3/T5.6 三处拦截：EQ(Purchase)<4 或后台订单 vs 归因差>30%→P0 修像素/CAPI/去重，修复前停止一切层内诊断；归因差≤20% 才放行。L4-06 收尾再校验一次（差>30~40% 判追踪问题）。
- **Q：样本不足能做细分诊断吗？**
  A：不能。T5.0/L4-01：近 14 天消耗 <$50 只做整站整体诊断不细分；L1-03 另有层级门槛——周转化≥50 脱离学习、20~50 学习中、<20 样本不足；T1.2 规定 Learning（<50 转化）期 Campaign 只看趋势不动策略。
- **Q：树里的 A-xx 动作编号是哪套？和 S4 动作库什么关系？**
  A：`[待确认]`。S7 决策树出口标注 A-03/A-04/05/A-07/A-08/A-13/A-14/A-15，但 sheet-08 动作库没有编号列，且这些编号与 S4 的 A-01~A-16 无法逐一对应（如 T1.4「扩预算20%(A-03)」在 S4 中 A-03 是 +50%）。语义上 S7 动作库 18 行与 S4 A-01~A-16 高度重叠，S7 多「降低出价目标」「调整落地页广告一致性」两项。
- **Q：S7 和 S4 阈值冲突时听谁的？**
  A：如实并列、按场景取口径。典型冲突：L4 数据门槛 S7=$50/14天 vs S4=$100+Purchase≥50；素材疲劳 S7=周环比-30% vs S4=CTR/峰值<0.70（指标定义不同）；3秒播放/完播阈值两套数值不同。执行级判定建议以 S4 节点 IF 条件为准，S7 作为业务语义与 SOP 步骤来源 `[推断]`。
- **Q：S7 的 P0/P1/P2 和 S4 一样吗？**
  A：同名三档但 S7 无独立定义节——P0 用于数据/合规/归因/跳戏类止血（修复像素、申诉、改 LP 承诺），P1 用于当日干预（调结构、换素材、修漏斗），P2 用于计划内优化（扩受众、扩预算 20%、文案测试）；S4 有显式定义并规定 P0 冻结普通优化动作。
- **Q：这套 SOP 适用什么业务场景？**
  A：Meta（Facebook/Instagram）广告，DTC 母婴/消费品为主（sheet-08/10 声明阈值为 DTC 中高客单 $100-300 经验值，实际±50% 浮动、大促放大 1.5-2x）；案例账户为 Momcozy（US-Pump-M5、US-Wearable-M9）。
- **Q：S7 和 S4 哪个更新？**
  A：无法从导出内容判断版本新旧 `[待确认]`。S7 文件名标 v7、S4 无版本号；S5 PRD 的产品化基于 S4 节点体系（65 节点/196 分支），说明 S4 是规则引擎的直接资产源。
