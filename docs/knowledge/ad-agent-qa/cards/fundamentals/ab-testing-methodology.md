# A/B 测试方法论 · 假设框架、样本量/MDE、peeking 禁忌、p 值解读与 guardrail 指标

## 核心问题

A/B 测试结果算不算数？样本量多少才够？能不能中途看一眼就停？p 值显著就能上线吗？本卡蒸馏 marketingskills 的 `ab-testing`——**实验纪律层**，是 KB 所有「测一下试试」动作的统计法庭。

## 系统解答

### 1. 来源与适用范围

- **来源**：`github.com/coreyhaines31/marketingskills` → `skills/ab-testing/`（MIT，`raw/s25-marketingskills/skills/ab-testing/`）。覆盖假设设计→样本量→运行→判读→文档全流程。
- **适用**：页面/素材/定价/功能的受控实验。**不适用**：广告平台内部的投放实验（Meta/Google 的 A/B 测试有各自学习机制，见各平台卡）；统计严谨性要求可按实验规模分级——大流量 DTC 站全套执行，小预算测试至少守住「预先定样本量+不偷看+预注册指标」三条。

### 2. 四条核心原则

1. **从假设出发**——不是「看看会怎样」，而是「因为 [观察/数据]，我们相信 [改动] 会让 [受众] 的 [指标] 变化 [幅度]」；
2. **一次只测一个变量**——不然不知道什么起作用；
3. **统计严谨**——预先定样本量、不偷看早停、承诺方法论；
4. **测真正重要的指标**——primary 绑业务价值、secondary 解释 why、guardrail 防止伤害。

假设强弱对比：弱「改按钮颜色可能提高点击」→强「因为热图和反馈显示用户找不到 CTA，我们相信放大按钮+对比色会让新访客 CTA 点击率提升 15%+，以 page view→signup start 点击率衡量」。

### 3. 测试类型与流量需求

| 类型 | 说明 | 流量需求 |
|------|------|---------|
| A/B | 两版本单变量 | 中 |
| A/B/n | 多变体 | 高 |
| MVT | 多改动组合 | 很高 |
| Split URL | 不同 URL | 中 |

流量分配：默认 50/50；保守 90/10 或 80/20 限制坏版本风险；ramping 小步放量用于技术风险。注意用户一致性（回访看到同一变体）和时段均衡。

### 4. 样本量速查（α=0.05 双侧、power=80%、两比例检验）

| 基线转化率 | 10% lift | 20% lift | 50% lift |
|:---:|:---:|:---:|:---:|
| 1% | 160k/变体 | 43k/变体 | 7.7k/变体 |
| 3% | 53k | 14k | 2.5k |
| 5% | 31k | 8.2k | 1.5k |
| 10% | 15k | 3.8k | 690 |

输入三要素：基线转化率、**MDE（最小可检测效应——值得检测的最小变化，由业务影响+实施成本+历史测试现实性三方定）**、显著性 α=0.05/power=80%。完整表见 `raw/s25-marketingskills/skills/ab-testing/references/sample-size-guide.md`（含时长计算公式、多变体校正、顺序检验）。

### 5. 指标三层结构

- **Primary**：唯一最重要、直接绑假设、用于判胜负（例：定价页测试→方案选择率）；
- **Secondary**：解释 primary 为什么/怎么起作用（停留时长、方案分布）；
- **Guardrail**：不该变差的指标，显著恶化即停测试（客服工单、退款率）。

### 6. Peeking 问题与 p 值解读纪律

- **Peeking**：达到样本量前看结果并提前停→假阳性和错误决策。预先承诺样本量，信任流程；
- **p 值正确理解**（ASA 声明口径）：p 值是在「原假设+其假设成立」下观测到至少这么极端结果的概率——**不是**「结果由随机造成的概率」、不是「原假设为真的概率」、不是「变体会再赢的概率」；95% CI 是重复抽样下的覆盖率程序性质，不是「这个区间含真值的后验概率 95%」。报告要同时给效应量+区间；
- **统计显著 ≠ 业务价值**：显著但效应量小/无 guardrail 通过/业务上不值得实施，都不该上线；
- **顺序检验/贝叶斯**有自己的解释框架，不要把平台「confidence」分数当固定期限 p 值用。

### 7. Opt-in 元素的特殊处理

改动只触达交互过的访客时（hero 视频、计算器、chat widget），按整体转化率测会欠功效（10% 点击率的元素让 90% 访客只贡献噪声）。两条路：①**triggered analysis**——两臂都记录同一触发点（如播放键进入视口），只比较到达者（⚠️ 不要按点击过滤，变体会改变谁点击）；②跳过受控测试直接上线更好版本，用版本 ID 标记做参与度/观看者转化的方向性对比——**这是方向性对比不是受控测试**。

### 8. 判读检查单

样本量到没到？（没到=preliminary）→ 统计显著？（看 CI）→ 效应量有业务意义？（对照 MDE）→ secondary 一致吗？→ guardrail 有问题吗？→ 分群差异？（移动/桌面、新老访客）→ 结论分四档：显著胜者（查效应量+guardrail 再上）/显著败者（留 control 学原因）/无显著差异（报效应区间，别把已结束的固定期限测试无限延长到显著——需要就开新测试）/信号混杂（查数据质量，未预注册的分群发现标 exploratory 并新测试验证）。

### 9. 运行纪律

测试前 checklist：假设文档化/primary 定义/样本量算好/变体实现正确/埋点验证/QA 过。运行中 DO：监控技术问题/查分群质量/记录外部因素；DON'T：偷看早停/改变体/引入新流量源。

## 高频问答索引

- **Q：A/B 测试跑到一半想停可以吗？**
  A：不行——peeking 是假阳性主因。预先算好样本量并承诺到底；没到量的结果只是 preliminary。若方向性对比够用（如 opt-in 元素），宁可跳过受控测试直接上线更好版本。
- **Q：样本量怎么算？**
  A：三输入——基线转化率、MDE（值得检测的最小变化）、α=0.05/power=80%。速查：5% 基线测 20% lift 需 8.2k/变体，测 10% lift 需 31k/变体。流量不够就调大 MDE 或换更高基线的页面测。
- **Q：p<0.05 显著就能上线吗？**
  A：不一定——显著只是「数据与原假设不兼容」的概率陈述，不是业务价值证明。还要看效应量是否过 MDE、guardrail 有没有变差、secondary 是否一致、分群是否有反向信号。
- **Q：一次想测标题+图片+CTA 三个改动行吗？**
  A：原则上一次只测一个变量。但小流量现实下可接受「整体改版 vs control」的巨型测试（测的是 bundle 不是单变量），结论要标注「不知道哪个起作用」；流量够则拆开测。
- **Q：opt-in 元素（如视频播放按钮）怎么测？**
  A：按整体转化率测会欠功效——用 triggered analysis（两臂同一触发点只比到达者，不按点击过滤）或干脆跳过受控测试做版本 ID 方向性对比。
