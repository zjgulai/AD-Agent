I环节 3 · 数据异常排查 10:30–12:00

环节目的：对 W 环节标记的"需排查"对象做五层穿透（账户 → Campaign → AdSet → Ad → 落地页），只查异常对象，逐层剥离，最终锁定 唯一根因层级。核心心法:先判"问题在哪一层"，再判"为什么"，最后才动。

I-1 · 根因快速分类（第一层判断）

I-1 · 现象→根因快速映射
I-1.1 IF 点击率(CTR) < 0.5% THEN 根因 = 素材问题（90%概率） → 进 C 环节，不看受众不看落地页 I-1.2 ELIF CTR 正常(≥0.8%)但 CVR 低(<1%) THEN 根因 = 落地页/站内漏斗 → 进 I-3 六层漏斗定位 I-1.3 ELIF CTR 与 CVR 都正常但 ROAS 低 THEN 查 AOV / 归因 / 转化事件口径 → 进 I-4 I-1.4 ELIF 整体正常但某 AdSet CPA 2x 均值 THEN 根因 = 受众 or 素材（需交叉验证） → 进 I-2 I-1.5 ELIF 某素材 CTR 周环比 -30%+ THEN 根因 = 素材疲劳（频次>4 佐证） → 进 C 环节上新

I-2 · 受众 vs 素材交叉验证（防误诊关键）

I-2 · 交叉验证决策树
I-2.1 取"差 AdSet"与"好 AdSet"共用的同一素材做对比 IF 同素材在好受众表现好、在差受众差 THEN 判定 = 受众问题 → B-4（关停差受众 / 单独降价30%） ELIF 差素材在所有受众都差 THEN 判定 = 素材问题 → C-1（换新方向素材） ELSE 数据不足以判定（样本<50转化） THEN 继续观察，不动作 #铁律:样本不足不判效

I-3 · 落地页六层漏斗定位(L4)

当判断落在站内，用六层漏斗找"断崖式下降的那一层"。每层对应不同根因:技术 / 承接 / 说服 / 摩擦 / 归因。
漏斗环节核心指标健康基准断崖时根因方向
曝光→点击出站CTR≥1%（素材）素材/文案/Offer → C
点击→落地页到达LPV/出站点击≥70%加载/链路/404 → 技术修复
到达→浏览内容VC/LPV≥60-70%首屏承接/信任元素 → 对齐广告

I-3 · 六层漏斗定位决策树
I-3.1 先验数据充分性: IF 近14天消耗 <$50 THEN 只做整站整体诊断，不细分 #防误诊 ELSE 进入六层逐层照 I-3.2 FOR 每层（到达→浏览→加购→结账→购买）: IF 该层转化率 < 健康基准 THEN 记为该层断崖，定位该层根因 ELIF 全层均达标但整体CVR仍低 THEN 根因在广告前段（素材/受众），回 I-1 I-3.3 IF 断点在"点击→到达"（到达率<60%） THEN 技术问题:PageSpeed 移动端 + 链接链路 → 修复后48h复测 I-3.4 IF 断点在"到达→浏览"（浏览率<60%） THEN 首屏承接:广告与 LP 同产品同承诺 + 信任元素首屏 I-3.5 IF 断点在"浏览→加购"(<3%) THEN 产品说服力:价格/评价（≥10带图）/利益点文案/SKU I-3.6 IF 断点在"结账"（IC/ATC<40% 或 Purchase/IC<50%） THEN 结账摩擦:运费前置/Guest/支付方式/信任 I-3.7 IF 归因兜底差异 >30% THEN P0:修 Pixel/CAPI/去重 → 48h 复测后再出结论

I-4 · 归因与结构排雷（现象异常但链路全正常时）

I-4 · 归因/结构排查决策树
I-4.1 IF 后台有单但归因购买少 THEN 像素漏报/去重失败 P0 → 修事件（算法失明，投放会持续变差） I-4.2 ELIF ROAS 崩但转化量正常 THEN 归因窗口/重复事件 → 先对口径，勿动投放 I-4.3 ELIF 多个 Campaign 同时崩（非单点） THEN 查账户级:政策受限/频次上限/Billing/大促波动 I-4.4 ELIF 仅单个 Campaign 崩 THEN 查该 Campaign 内部（AdSet/素材）→ 回 I-2/I-1
排雷原则：归因/事件/落地页这三类 P0 不排除，任何层内结论都可能是假象。I 环节结束时必须能回答:问题在哪个层级？证据值是多少？根因是什么？该走 B/C/L4 哪个动作？

B环节 4 · 预算与出价调整 13:00–14:30

环节目的：把 I 环节的根因结论翻译成具体的预算/出价动作。铁律:一次只动 1 个变量;根因是素材就绝不调预算（那是放大无效消耗）。

B · 预算/出价调整决策树
B-1 IF 根因 = 素材问题（CTR低/疲劳） THEN 预算分文不动 → C 环节换素材 #在烂素材上扩预算=放大浪费 B-2 IF Pacing <60%（欠投，且非素材问题） THEN 依次试:① 出价上限 +15% → ② 放宽受众 → ③ 查频控 每步间隔24h，只动一项 B-3 IF Pacing >130%（超投）或预算将尽 THEN 立即降日预算 20% 止血（晚间值守也适用） → 查 CBO 是否偷预算 B-4 IF 确认受众问题（交叉验证通过） THEN 关停劣质 AdSet 或单独降价 30% → 48h 看整体 CPA 是否改善 B-5 IF 确认可扩量对象（ROAS≥1.3x,Learning 完成） THEN 扩预算 20%（一次不超+50%，分2-3次） → 48h 后看 ROAS 是否守住 B-6 IF 出价达成率 <0.7x 持续3天 THEN 先查是"目标虚高"还是"竞争上涨" 目标虚高→调到可行值;竞争→备素材/容忍短期 B-7 IF 目标达成 >1.3x（远好） THEN 小幅上调目标 10-15% 榨量，勿一次调太多 B-8 IF Learning 未满 50 转化 THEN 禁止动预算（每次编辑重置学习） ELSE 按上述分支执行

C环节 5 · 素材上新管理 14:30–16:00

环节目的：素材是命根。每天固定窗口处理:识别需替换素材 → 给创意团队可执行需求单 → 上新跟踪 → 新素材保护（给足学习期）。

C · 素材上新决策树
C-1 IF 素材 CTR <0.5% 或 周环比-30%+（疲劳） THEN 列"需替换" → 输出需求单（3-5条新方向） ELSE 保持观察，进入 C-2 C-2 IF 视频 3秒播放率 <20% THEN 重剪前3秒（hook前置）+ 换封面 C-3 ELIF 完播率 <5%（3秒率正常） THEN 节奏加速/砍冗长开头/提信息密度 C-4 IF 文案首行无钩子（无数字/痛点/限时） THEN 重写首行:对谁说+问题+方案+行动 C-5 IF CTA 与落地页承诺不一致（跳戏） THEN P0:以落地页为准改广告，当天修 C-6 IF 新素材上线 <3 天或点击 <50 THEN 保护期:不做判定，不做删除 ELSE 按 CTR/转化评估去留 C-7 IF 素材库周净增 <3 条新方向 THEN 预警创意产能 → 提前排素材档期
给创意团队的需求单格式：① 替换对象（哪条素材、上线天数、CTR 多少）② 失败原因（视觉/首屏/文案/疲劳）③ 新方向建议（人群×场景×卖点，不要同主题微调）④ 交付时间(48h)。

R环节 6 · 效果复盘 16:00–17:00

环节目的：闭环日循环:回看 72h 前的动作是否达预期;判定 A/B 测试;检查学习期是否脱离;沉淀"赢家特征"。

R-1 · 动作回看（72h 验证窗口）

R-1 · 动作效果判定树
R-1.1 取动作日志中所有已到 72h 的动作: FOR 每条动作: IF 实际指标达成预期(±15%) THEN 标记"有效，固化" → 考虑是否放量或推广到同类 ELIF 未达成预期 THEN 标记"无效，回滚或换动作" → 记录根因（误诊？执行错？外部变化？） ELIF 数据不足以判断（样本<50/大促期） THEN 延长观察 48h，暂不下结论

R-2 · A/B 测试判定

R-2 · A/B 判定决策树
R-2.1 FOR 每个进行中的 A/B: IF 样本不足（转化 <50/组） THEN 继续跑，不出结论 ELIF 胜者明显（胜率 >60% 或 CPA 差 >20%） THEN 淘汰输家 → 胜者放量或转正 ELIF 结果接近（无统计差异） THEN 按成本/可扩展性人工选型 → 或加大样本再测 R-2.2 IF 新素材 3 天 0 转化且点击>50 THEN 淘汰，换新方向（勿同主题微调）

F附录 · 资产整合映射与核对方法

v1~v4 → v5/v6 融合去向
【SOP 深度整合说明 · v1~v4 资产去向】 本终稿并非将 v1~v4 机械罗列，而是先建立"一名 Meta 投放师的一天"为主干，再按时间/场景把历代资产分配到最自然的环节，并在每环节内自洽闭环（前置→步骤→记录→异常→判定→交接），无需跳查其他表。 - v1.0（全平台分层诊断） → 其"诊断铁律/五步法/动作影响四要素"被吸收为全文总纲与 A2 动作库; - v2.x（五层决策表+六层漏斗） → 决策表每一行被重写为环节内的 IF/ELSE 决策节点（编号 W/I/B/C…），六层漏斗阈值并入 I-3 六层漏斗树; - v3.0（六维操作规程） → 六维（前置/步骤/记录/异常/判定/交接）被压入每个环节的"标准操作规程"小节，字段与记录格式随环节呈现; - v4.0（四代融合矫正） → 其矫正结论（口径统一/优先级/数据充分性/归因兜底）成为全文阈值基准(A1)与各决策节点的"阈值依据"列; - 编号体系:环节字母 M/W/I/B/C/R/D/P + 节点序号，HTML 与 Excel 同名同号，逐项可核对。 逐项核对方法:任取一条真实数据 → 从 G 全局树进入对应环节 → 按环节决策节点逐条 IF 判定 → 命中 THEN 执行并记入 A3 动作日志 → 72h 后回 R 环节核对。
