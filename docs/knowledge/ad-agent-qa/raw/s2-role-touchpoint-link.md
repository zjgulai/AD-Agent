# 02 红人广告加推 Agent Loop · 角色·触点·链路全景梳理

> 本文档梳理红人广告加推 Agent Loop 场景下的用户角色、交互触点和每个 Agent 的完整交互链路。  
> 覆盖平台：TikTok、Instagram（Meta）、YouTube（Google）

---

## 一、用户角色（3 个核心角色）

| 角色 | 职责 | 关键决策点 | 主要使用系统 |
|-|-|-|-|
| **红人推广负责人** | 管理红人内容池与红人资源，判断素材价值，索要视频授权，关注红人广告表现沉淀经验 | ① 确认/拒绝潜力素材加推 ② 发起授权索要 ③ 登记授权码 ④ 查看复盘报告 ⑤ 主动问询效果数据 | 红人系统 + 飞书 IM |
| **广告负责人** | 管理广告投放策略、预算、上线和优化 | ① 确认广告加推策略 ② 确认广告正式投放 ③ 确认优化建议 ④ 处理上线检查异常 ⑤ 查看日报/复盘 | 广告系统 + 飞书 IM + 三方广告平台 |
| **红人** | 内容创作者，提供视频授权 | 接收授权邀约、提供授权码 | 邮件（外部协作） |

> 注：红人为外部角色，通过 IM/邮件交互。红人推广负责人同时承担红人资源管理和内容加推决策职责。

---

## 二、交互触点（5 个系统 + 飞书 IM 贯穿全程）

| 触点 | 形态 | 核心作用 | 主要使用者 |
|-|-|-|-|
| **飞书 IM** | 智能体对话 + 卡片消息 | Agent 推送通知、人工确认（HITL）、主动问询效果、日报/周报推送、授权索要通知 | 全部角色 |
| **红人系统** | Web 界面·内容池页 | 浏览红人内容、查看素材基础信息、AI 潜力标签/评分展示、授权状态管理、加推确认操作 | 红人推广负责人 |
| **广告系统** | Web 界面·广告列表/详情/编辑页 | 查看广告策略、编辑广告、批量操作、异常广告列表、跳转三方平台 | 广告负责人 |
| **三方广告平台 × 3** | TikTok Ads / Meta Ads / Google Ads 后台 | 最终广告创建与投放的真实平台（Demo 中可做跳转示意） | 广告负责人 |
| **邮件 / 外部 IM** | Gmail / Outlook / WhatsApp 等 | 向外部红人发起授权邀约、回收授权码 | 红人推广负责人 ↔ 红人 |

**关键设计原则**：飞书 IM 是 Agent 的"嘴"——所有通知、确认、问询都走 IM；业务系统是 Agent 的"手"和"眼"——数据读取、操作执行、详情查看走系统界面。

## 四、完整 Agent 交互链路（含新增授权 HITL）

### ① 红人素材发现 Agent

| 维度 | 详情 |
|-|-|
| **触发** | 定时触发（如每 2 小时扫描一次三平台红人内容池） |
| **输入** | 红人系统内容池数据（TikTok / Instagram / YouTube 三平台视频数据：播放量、互动、发布时间、产品标签） |
| **处理逻辑** | 规则过滤（产品相关、品牌安全、时长适配）→ AI 内容理解（产品出现、Hook、卖点、场景）→ 广告潜力初筛 |
| **输出展示位置** | 红人系统内容池：每条内容旁出现「AI 推荐加推」标签 + 平台标识 + 推荐原因浮层  <br/>飞书 IM：推送「今日新发现 N 条潜力素材」摘要卡片，点击跳转红人系统内容池 |
| **跳转逻辑** | IM 卡片 → 红人系统内容池（自动筛选"AI 推荐"状态） |
| **HITL** | 无（纯发现，不做决策） |

---

### ② 红人素材潜力评分 Agent

| 维度 | 详情 |
|-|-|
| **触发** | 素材发现 Agent 输出新素材后自动触发 |
| **输入** | 发现 Agent 筛选出的候选素材 + 红人历史广告表现数据 + 产品数据 + 平台属性 |
| **处理逻辑** | 6 维度评分（内容质量 20% + 自然互动 15% + 产品匹配 20% + 人群匹配 15% + 历史表现 20% + 品牌安全 10%）→ 输出 Ad Potential Score + 推荐投放平台建议 |
| **输出展示位置** | 红人系统内容池：每条素材显示评分分数 + 等级（强烈推荐/推荐测试/观察/不推荐）+ 推荐平台标签  <br/>飞书 IM：推送「潜力素材榜单」卡片（Top 5 + 评分 + 推荐理由 + 推荐平台） |
| **跳转逻辑** | IM 卡片 → 红人系统内容池（按评分排序视图）  <br/>点击单条素材 → 红人系统素材详情页 |
| **HITL** | 无（纯评分，决策在下一节点） |

### ②.5 HITL：红人授权索要（新增节点）

| 维度 | 详情 |
|-|-|
| **触发** | 潜力评分 Agent 输出"强烈推荐 + 推荐测试"等级素材后，自动检查授权状态 → 未授权素材进入授权索要流程 |
| **输入** | 待授权素材列表（素材缩略图、红人、平台、评分、推荐理由） |
| **交互方式** | 红人系统内容池：「待授权」标签 + 批量发起授权索要按钮  <br/>飞书 IM：推送「待授权素材清单」卡片给红人推广负责人  <br/>授权方式：① 飞书 IM 发消息给红人 ② 邮件发送授权邀约模板 |
| **授权码登记** | 红人回复授权码后，红人推广负责人在红人系统素材详情页登记授权码 + 授权有效期  <br/>或 Agent 自动识别 IM/邮件中的授权码并自动登记 |
| **确认后动作** | 授权完成的素材 → 自动进入"待确认加推"池 → 可进入下一步运营确认 |
| **跳转逻辑** | IM 待授权卡片 → 红人系统待授权素材列表  <br/>素材详情页 → 授权信息模块（授权状态、授权码、有效期） |
| **决策者** | 红人推广负责人（发起授权 + 登记授权码）  <br/>红人（提供授权） |

---

### ③ HITL：运营确认是否加推

| 维度 | 详情 |
|-|-|
| **触发** | 素材完成授权后，自动进入待确认加推池 |
| **输入** | 已授权 + 高评分的潜力素材列表（素材缩略图、红人、平台、评分、授权状态、推荐理由） |
| **交互方式** | 红人系统内容池：批量勾选 + 「确认加推」/「观察」/「拒绝」按钮  <br/>飞书 IM：推送待确认卡片，支持单条操作 + 批量通过 |
| **确认后动作** | 已确认素材 → 进入广告加推策略阶段 → 飞书 IM 推送通知给**广告负责人** |
| **跳转逻辑** | IM 确认卡片 → 红人系统待确认素材列表  <br/>确认完成后 IM 通知广告负责人 → 点击跳转广告系统"待策略素材"列表 |
| **决策者** | 红人推广负责人 |

### ④ 广告加推策略 Agent（按平台拆分：TikTok / Meta / YouTube）

| 维度 | 详情 |
|-|-|
| **触发** | 运营确认加推的素材进入策略池后，按平台分别触发 |
| **输入** | 红人素材信息 + 产品信息 + 各平台历史广告数据 + 红人受众画像 + 当前预算池 + 平台属性 |
| **处理逻辑** | 自动生成 Ad Boost Plan（每个平台独立生成）：  <br/>• TikTok：Campaign 目标、Audience（Broad/Interest/Lookalike）、版位（In-Feed/Spark Ads）、预算、测试方案  <br/>• Meta：Campaign 目标、Audience（Broad/Interest/LAL）、版位（Feed/Reels/Stories）、预算、测试方案  <br/>• YouTube：Campaign 目标、受众类型（In-Market/Affinity/Remarketing）、广告格式（Skippable/Shorts）、预算、测试方案 |
| **信息缺失处理** | 若缺少关键信息（如目标国家、预算上限、特定平台素材格式要求），飞书 IM 主动询问广告负责人，问答补齐后继续生成 |
| **输出展示位置** | 广告系统：「待确认策略」列表页，每条素材对应 1-3 个平台的策略卡片（含平台标识、国家、受众、兴趣词、预算、周期、KPI）  <br/>飞书 IM：推送「策略已生成，待确认」卡片，点击查看完整策略 |
| **跳转逻辑** | IM 卡片 → 广告系统待确认策略列表（可按平台筛选）  <br/>单条策略点击 → 广告系统策略详情页（可编辑） |
| **HITL** | 广告负责人按平台批量确认策略 → 确认后进入广告创建阶段 |

### ⑥ 广告创建 Agent（按平台拆分：TikTok / Meta / YouTube）

| 维度 | 详情 |
|-|-|
| **触发** | 各平台策略确认 + 素材就绪后，分别触发对应平台的创建 Agent |
| **输入** | Ad Boost Plan + 红人视频素材（已授权）+ 平台特定配置 |
| **处理逻辑** | 拟定广告计划（Campaign / Ad Set / Ad 结构）→ 调用**上线检查 Agent**进行合规检查 → 检查通过 → 调用对应平台 API 创建广告草稿：  <br/>• TikTok Agent → TikTok Ads API  <br/>• Meta Agent → Meta Marketing API  <br/>• YouTube Agent → Google Ads API |
| **输出展示位置** | 广告系统：「新建广告草稿」列表，按平台 Tab 分组，状态为「待上线检查」→「检查通过」→「草稿已创建」  <br/>飞书 IM：推送「广告草稿已创建」卡片（按平台汇总），附广告列表链接 + 各平台后台链接 |
| **跳转逻辑** | IM 卡片 → 广告系统广告列表（筛选"新建草稿"+ 平台筛选）  <br/>点击单条广告 → 广告系统广告详情页 → 可跳转对应平台后台 |
| **HITL** | 广告负责人手动打开广告（正式投放确认），可按平台批量开启 |

### ⑦ 上线检查 Agent（统一引擎 + 平台差异化规则）

| 维度 | 详情 |
|-|-|
| **触发** | 各平台广告创建 Agent 拟定广告计划后自动调用（独立 Agent，被调用模式） |
| **输入** | 待创建的广告计划（命名、设置、UTM、预算、素材、受众、Pixel/TikTok Pixel/Google Tag）+ 平台标识 |
| **检查维度** | 通用检查（7 项）：素材授权 / UTM 规范 / 追踪配置 / 命名规则 / 预算阈值 / 品牌安全 / 禁用词  <br/>平台差异化检查：  <br/>• TikTok：Spark Ads 授权码有效性、视频时长适配  <br/>• Meta：版权合规、Reels 格式适配、Pixel 事件匹配  <br/>• YouTube：TrueView 格式、Google Ads 关联状态、频道关联 |
| **检查不通过** | 暂停该平台的创建 → 飞书 IM 推送异常通知给广告负责人 → 卡片包含：问题清单 + 平台标识 + 「跳转到广告系统修改」链接 → 修改后重新触发检查 |
| **检查通过** | 反馈给对应平台的广告创建 Agent，继续完成创建动作 |
| **输出展示位置** | 广告系统：广告详情页显示「上线检查报告」（✓ / ⚠ / ✕ 逐项展示，标注平台差异项）  <br/>飞书 IM：异常时推送阻断卡片，通过时静默流转 |
| **跳转逻辑** | IM 异常卡片 → 广告系统广告编辑页（直接定位到问题字段） |
| **HITL** | 异常时需广告负责人手动修改并重新触发检查 |

### ⑧ 广告监控 Agent（三平台统一监控）

| 维度 | 详情 |
|-|-|
| **触发** | 定时触发（每小时扫描全量广告，覆盖三平台） |
| **监控范围** | 不仅限于加推广告，覆盖**全量广告**（TikTok + Meta + YouTube） |
| **监控指标** | Spend、Impressions、CTR、CVR、CPA、ROAS、消耗速度异常 |
| **异常判定** | 消耗突增/突降、CTR 骤降、ROAS 跌破阈值、零花费、花费过快（各平台阈值可独立配置） |
| **输出展示位置** | 广告系统：「异常广告」列表页，按平台 + 异常类型分类  <br/>飞书 IM：异常时推送告警卡片（异常广告数 + 分平台统计 + 核心指标变化 + 异常类型） |
| **跳转逻辑** | IM 告警卡片 → 广告系统异常广告列表（按异常类型 + 平台筛选）  <br/>点击单条 → 广告系统广告详情页 |
| **HITL** | 无（纯监控告警，决策由效果分析/优化 Agent 承接，或人工自行处理） |

### ⑨ 广告效果分析 Agent（三平台统一分析）

| 维度 | 详情 |
|-|-|
| **触发** | 两种模式：① 被动日报（每日定时推送）② 主动问询（飞书智能体对话触发） |
| **分析范围** | 不仅限于加推广告，覆盖**全量广告**（三平台汇总 + 分平台对比） |
| **分析维度** | 素材层（哪个红人素材表现最好）、红人层（哪个红人广告价值最高）、平台层（哪个平台 ROI 最高）、Campaign 层（哪个投放组合最优） |
| **核心能力** | 不只报数据，而是**解释原因**——如"TikTok CTR 高但 CVR 低 → Hook 吸引但落地页承诺不一致"；跨平台对比分析 |
| **输出展示位置** | 飞书 IM：每日推送「广告效果日报」卡片（核心指标 + 分平台对比 + Top/Bottom 素材 + 关键发现）  <br/>主动问询：智能体对话形式回答，回答中附跳转链接 |
| **跳转逻辑** | 日报卡片 → 广告系统效果分析 Dashboard  <br/>对话中提及具体广告 → 跳转广告系统广告详情页  <br/>对话中提及平台 → 跳转仪表盘对应平台 Tab |
| **使用者** | 广告负责人 + 红人推广负责人（均可主动问询） |
| **HITL** | 无（纯分析输出） |

### ⑩ 广告优化 Agent（三平台优化 + 统一管理）

| 维度 | 详情 |
|-|-|
| **触发** | 效果分析 Agent 输出分析结论后自动触发，或监控 Agent 发现异常时触发 |
| **优化维度** | Budget（加/降预算）、Audience（扩量/收窄）、Creative（替换/变体）、Bid（调出价）、Campaign（合并/暂停）  <br/>各平台有差异化优化手段：  <br/>• TikTok：Spark Ads 热度扩量、Creative Package 优化  <br/>• Meta：Advantage+ 自动扩量、CBO 调整  <br/>• YouTube：TrueView 到 Shorts 格式切换、受众信号调整 |
| **自动化分级** | Level 1（Recommend）：只给建议 → 推送 IM 待确认  <br/>Level 2（Approve）：执行前人工确认 → IM 卡片审批  <br/>Level 3（Auto）：低风险动作自动执行（如低效素材降预算 10%） |
| **输出展示位置** | 广告系统：「优化建议」列表，按平台分类，每条建议附预期收益 + 风险等级 + 平台标识  <br/>飞书 IM：推送「优化建议待确认」卡片（建议内容 + 预期效果 + 风险等级 + 平台 + 批准/拒绝/修改按钮） |
| **跳转逻辑** | IM 确认卡片 → 广告系统优化建议列表（按平台筛选）  <br/>点击单条 → 广告系统广告详情页（可手动编辑验证）  <br/>确认执行后 → 调用对应平台的广告创建 Agent 进行广告调整 → 完成后 IM 通知 |
| **HITL** | 中高风险动作需广告负责人确认；低风险动作自动执行后 IM 通知 |

### ⑬ 红人素材广告复盘 Agent（跨平台汇总）

| 维度 | 详情 |
|-|-|
| **触发** | 定时触发（每日日报 / 每周周报），或针对特定加推批次触发 |
| **复盘范围** | 近期在生效的红人加推视频广告（跨三平台汇总） |
| **复盘内容** | ① 红人内容数据：近 7 天播放量、互动趋势（分平台）  <br/>② 广告数据：曝光、点击、转化趋势（分平台 + 汇总）  <br/>③ 平台对比：各平台 ROAS / CPA / CTR 对比，最佳投放平台建议  <br/>④ 分析结论：优质视频特征、广告优化建议、预算调整建议（含平台间预算分配）  <br/>⑤ 下一步：哪些继续加推、哪些红人继续合作、哪些创意复制、哪个平台加码 |
| **输出展示位置** | 飞书 IM：推送「红人加推复盘报告」卡片（日报/周报），同时 @广告负责人 + @红人推广负责人  <br/>红人系统：红人详情页增加「广告表现」Tab，展示该红人各平台加推视频的复盘数据  <br/>广告系统：效果分析仪表盘「复盘报告」Tab |
| **跳转逻辑** | IM 复盘卡片 → 广告系统复盘 Dashboard  <br/>提及具体红人 → 跳转红人系统红人详情页  <br/>提及具体视频 → 跳转红人系统素材详情页  <br/>提及具体平台 → 跳转对应平台数据分析视图 |
| **接收者** | 广告负责人 + 红人推广负责人（双方同时收到） |
| **HITL** | 无（纯复盘输出，反哺下一轮素材发现，形成 Loop 闭环） |

## 五、系统间跳转总览

```
飞书 IM ──→ 红人系统（内容池/素材详情/红人详情/待授权/待确认列表）
   │         │
   │         └── 授权索要 → 邮件/外部IM → 红人（提供授权码）
   │
   └──→ 广告系统（待策略列表/待确认策略/广告列表/异常广告/优化建议/效果分析/编辑页）
            │
            ├──→ TikTok Ads 后台
            ├──→ Meta Ads 后台
            └──→ Google Ads 后台（YouTube）
```

**跳转设计原则**：

1. **IM 消息永远带跳转链接**——任何通知、确认、报告都能一键跳到对应系统的对应页面
2. **系统内跳转带上下文**——从 IM 点过去，自动筛选/排序/定位到具体对象
3. **跨系统跳转有明确回退路径**——广告系统 → 三方平台后，能原路返回
4. **平台标识贯穿全程**——所有卡片、列表、详情页都标注平台来源（TikTok/Meta/YouTube）

## 六、完整 Loop 跳转链路

按 Loop 顺序梳理完整跳转链路：

```
【Loop 起点】
  Loop 总览页
    ↓ 点击"素材发现"节点
【红人系统】
  红人内容池页（①发现 + ②评分 + 平台标识）
    ↓ 未授权素材 → 授权索要 HITL
  红人内容池页（待授权视图 + 授权码登记）
    ↓ 授权完成 → 进入待确认加推池
  红人内容池页（③HITL 运营确认加推）
    ↓ 点击"确认加推" → IM通知广告负责人
【飞书 IM】
  IM 推送"待确认加推"卡片（含平台标识）
    ↓ 点击"跳转到加推工作台"
【广告系统】
  加推工作台页（④三平台策略生成 + 信息补全 + 批量确认）
    ↓ 点击"确认加推" → ⑥三平台创建广告草稿 → ⑦上线检查
  广告列表页（草稿状态 + 平台Tab + 上线检查状态标签）
    ↓ 点击广告名称
  广告详情页（上线检查报告 Tab + 平台差异化检查项）
    ↓ 检查通过 → 手动开启投放
  广告列表页（投放中状态 + 平台Tab）
    ↓ ⑧监控发现异常 → IM告警
【飞书 IM】
  IM 推送"异常告警"卡片（分平台统计）
    ↓ 点击"查看异常广告列表"
【广告系统】
  广告列表页（异常筛选状态 + 平台Tab）
    ↓ 点击广告
  广告详情页（优化建议 Tab + 平台差异化优化手段）
    ↓ ⑩优化建议 → IM推送确认
【飞书 IM】
  IM 推送"优化建议待确认"卡片（含平台标识）
    ↓ 点击"确认执行" → 调用对应平台广告创建Agent调整
  IM 推送"执行完成"通知
    ↓ 每日/每周 ⑬复盘
  IM 推送"复盘报告"卡片（跨平台汇总 + 分平台对比）
    ↓ 点击"跳转效果分析仪表盘"
【广告系统】
  效果分析仪表盘（素材/红人/平台/Campaign 四维度 + 复盘报告）
    ↓ 点击素材 → 跳回红人系统
【红人系统】
  素材详情页（广告表现数据 + 分平台对比）
    ↓ 反哺下一轮素材识别
  ↺ Loop 闭环
```
