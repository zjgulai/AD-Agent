# 診斷工具整合定義

> 定義每個診斷維度使用哪些工具、用工具做什麼、產出什麼。
> 原則：工具是為了「拿到證據」，不是為了炫技。報告中每個扣分項都應有工具取得的證據（截圖、資料、實測結果）。

## 工具總覽

| 工具 | 用途 | 產出物 |
|---|---|---|
| Agent Reach | 市場調研、競品調研、當地消費習慣與口碑蒐集 | 調研摘要、引用來源清單 |
| Browser / Playwright | 實測官網：購物流程、速度、移動端、事件觸發 | 截圖、流程錄影、事件觸發記錄 |
| Imagegen | 生成報告視覺素材（雷達圖佔位、封面圖、改善示意） | PNG/JPG 圖片 |
| AEO/GEO 內容教練 | 評估內容結構、產出 FAQ/Schema 改造建議 | 內容診斷與改寫示範 |
| Meta Ad Library | 查競品與客戶自己的在投廣告 | 競品素材清單、投放角度分析 |

## 一、品牌定位 × 工具

| 任務 | 工具 | 具體做法 | 產出 |
|---|---|---|---|
| 競品識別 | Agent Reach | 搜「{品類} {市場} 品牌 推薦」，整理 Top 5 競品 | 競品清單 |
| 品牌聲量檢查 | Agent Reach | 搜品牌名+市場詞，看第三方提及 | 聲量摘要 |
| 視覺一致性檢查 | Browser | 截圖官網首屏、IG 近 9 帖、商品頁 | 對比截圖 |
| 競品廣告主張 | Meta Ad Library | 查 Top 5 競品在投素材的文案主張 | 主張對比表 |

## 二、官網健康度 × 工具

| 任務 | 工具 | 具體做法 | 產出 |
|---|---|---|---|
| 結賬流程實測 | Playwright | 加購 → 結賬 → 到支付頁，記錄步數、欄位數、支付方式 | 流程截圖+步驟清單 |
| 速度實測 | Browser | 跑 PageSpeed Insights（移動端+桌面端） | 分數截圖 |
| 移動端體驗 | Browser | 移動端視口截圖首頁/商品頁/結賬頁 | 截圖 |
| 運費透明度 | Playwright | 實測運費在購物流程哪一步才出現 | 記錄 |
| 信任要素檢查 | Browser | 檢查退換貨政策、聯絡方式、評價區 | 檢查表 |

## 三、SEO/AEO/GEO × 工具

| 任務 | 工具 | 具體做法 | 產出 |
|---|---|---|---|
| 收錄檢查 | Browser | `site:域名` 搜尋，檢查 robots.txt、sitemap | 收錄頁數 |
| 結構化資料檢查 | Browser | 跑 Rich Results Test 檢查 FAQ/Product schema | 檢測結果 |
| AI 能見度實測 | Agent Reach | 問 ChatGPT/Gemini/Perplexity：「推薦 {品類} 品牌」「{品牌} 評價如何」 | 回答記錄 |
| 內容結構診斷 | AEO/GEO 內容教練 | 輸入 2-3 篇代表內容，產出 AEO/GEO 改造建議 | 診斷+改寫示範 |
| 圖片 ALT 抽查 | Browser | 抽查 20 張圖 ALT 屬性 | 檢查表 |

## 四、廣告準備度 × 工具

| 任務 | 工具 | 具體做法 | 產出 |
|---|---|---|---|
| Pixel 事件實測 | Browser（Pixel Helper） | 觸發 ViewContent/AddToCart/Purchase，記錄事件與引數 | 事件觸發記錄 |
| 客戶在投廣告檢查 | Meta Ad Library | 搜客戶品牌名，看是否有在投廣告及素材質量 | 素材清單 |
| 競品廣告調研 | Meta Ad Library | 搜 Top 5 競品，整理素材型別/角度/頻次 | 競品素材分析 |
| 落地頁一致性 | Browser | 對比廣告文案 vs 落地頁首屏 | 對比截圖 |

## 五、私域 × 工具

| 任務 | 工具 | 具體做法 | 產出 |
|---|---|---|---|
| 私域入口檢查 | Browser | 官網找私域導流入口（訂閱框/WhatsApp/LINE） | 截圖 |
| 當地私域生態確認 | Agent Reach | 確認該市場主流私域平臺與工具 | 平臺建議 |
| 自動化流程盤點 | 客戶提供 + Browser | 檢查是否有歡迎/棄單/售後流程 | 流程清單 |

## 六、報告視覺 × 工具

| 任務 | 工具 | 具體做法 | 產出 |
|---|---|---|---|
| 雷達圖 | 報告模板內嵌 Chart.js | 用 6 維度評分生成雷達圖（不依賴 Imagegen） | 雷達圖 |
| 報告封面視覺 | Imagegen | 生成品類相關的封面背景圖（如寵物→溫暖插畫） | 封面圖 |
| 改善示意圖 | Imagegen | 可選：為關鍵建議生成 before/after 示意圖 | 示意圖 |

## 工具使用順序（標準診斷流程）

1. **Browser/Playwright 先跑**：官網實測（速度、結賬流程、移動端）——10 分鐘拿硬證據
2. **Pixel Helper 檢查**：事件觸發實測——5 分鐘
3. **Meta Ad Library**：客戶與競品廣告盤點——10 分鐘
4. **Agent Reach**：市場調研 + AI 能見度實測 + 口碑蒐集——15 分鐘
5. **AEO/GEO 內容教練**：內容診斷——10 分鐘
6. **Imagegen**：報告視覺素材（可選）——5 分鐘

## 降級策略（工具不可用時）

| 工具不可用 | 降級方案 |
|---|---|
| Playwright 無法執行 | 改用人工瀏覽器實測 + 截圖，記錄相同檢查項 |
| Agent Reach 失敗 | 改用直接 WebSearch/Google，標註「調研深度受限」 |
| Meta Ad Library 無法訪問 | 改搜競品 FB/IG 主頁「廣告透明度」區塊 |
| Imagegen 失敗 | 報告視覺用純 CSS/圖表庫替代，不阻塞交付 |
| AEO/GEO 教練不可用 | 用 `checklists/seo-aeo-geo.md` 人工逐項評分 |

## 證據存放約定

- 診斷過程中的截圖、記錄統一放在報告輸出目錄的 `evidence/` 子目錄
- 報告內引用證據時標註來源（如「證據：evidence/checkout-flow.png」）
- 敏感資訊（客戶後臺資料）不截圖、不入報告，只描述結論
