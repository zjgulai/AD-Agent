# Meta 广告诊断与优化 Q&A

覆盖 `cards/meta-ads-diagnosis/`（8 卡）。本集群源文档最多、口径冲突最集中——凡涉阈值类问题，答案并列呈现各源口径并注明出处，执行级判定建议以 S4 策略树节点 IF 条件为准 `[推断]`。

### Q1. Meta 广告诊断必须按什么顺序执行？能跳过前置检查吗？
**A**：不能跳过。S4 策略树固定顺序 G0 数据可信度 → G1 资格 → G2 追踪归因 → G3 目标事件 → G4 样本 → G5 预算 → G6 专项 → G7 分层 → G8 安全 → 复核，任一阶段命中异常出口即在该阶段收口。S7 Agent 训练版用 T0–T5 决策树+L0–L4 五层组织同一逻辑：先 T0 前置排雷（EQ/归因差异、账户受限、落地页可达），再 T1 查 Campaign、T2 按症状路由、T3 受众、T4 素材、T5 逐层穿透六层漏斗。S6 人类 SOP 按一天 8 环节（M/W/I/B/C/R/D/P）编排执行节奏。三套文档同源异构，节点编号体系互通。
> 溯源：`meta-diagnosis-sop.md` / `meta-diagnosis-sop-agent-training.md` / `meta-diagnosis-layers-l0-l4.md` / `meta-operator-daily-workflow.md`

### Q2. P0、P1、P2 怎么分？P0 会冻结什么？
**A**：S4 显式定义：P0 立即止血（如 ROAS<盈亏平衡×0.7、落地页不可达、EQ<4）、P1 当日干预、P2 计划内优化；P0 冻结普通优化动作，只允许止血/修复类动作。S7 同名三档但无独立定义节：P0 用于数据/合规/归因/跳戏类止血（修像素、申诉、改 LP 承诺），P1 用于当日干预（调结构、换素材、修漏斗），P2 用于计划内优化（扩受众、扩预算 20%、文案测试）。
> 溯源：`meta-diagnosis-sop.md` / `meta-diagnosis-sop-agent-training.md`；详见 `CONFLICTS.md`

### Q3. 动作铁律具体有哪些？
**A**：一次只动一个主变量（不得同时改预算、出价、素材、人群）；学习期不判效；动作后必须 4h/24h/72h 复核；冷却期 24h～72h；归因窗口成熟度 ≥80% 才允许正常判断 CPA/ROAS，未成熟仅预警。同日禁止预算+受众+素材连环改（无法归因）。
> 溯源：`meta-diagnosis-sop.md` / `meta-operator-daily-workflow.md`

### Q4. 数据不可信/归因差异怎么办？
**A**：先修归因口径再谈优化（对应动作 A-16）。各检查点口径不同：S7 T0.1/L0-01 用 EQ(Purchase)<4 或后台订单 vs 归因差>30%→P0 修像素/CAPI/去重，归因差≤20% 才放行；S7 L4-06 收尾校验差>30~40% 判追踪问题；S4 G2/G3 以 EQ<4 或订单差异>30% 收口。归因异常时修复 Pixel/CAPI/去重后等 48h 数据稳定再诊断，期间任何层内结论可能是假象。
> 溯源：`meta-diagnosis-sop.md` / `meta-diagnosis-layers-l0-l4.md` / `meta-diagnosis-sop-agent-training.md`；冲突见 `CONFLICTS.md`

### Q5. 样本不足能做诊断吗？门槛是多少？
**A**：三套门槛并存——S4 P0-05：花费<$50 且 Purchase<30 仅延长观察；$50~100 或 Purchase 30~50 标低置信度 7 天后复测；≥$100 且 ≥50 进入正式诊断（广告组级另有 S2-01 ≥$100 且转化≥30）。S7 L4-01：近 14 天消耗≥$50 才可逐页细分，否则只做整站整体诊断+置信度标注；L1-03 另有层级门槛——周转化≥50 脱离学习、20~50 学习中、<20 样本不足。S6 I-3：近 14 天消耗<$50 只做整站整体诊断。执行级以 S4 为准 `[推断]`。
> 溯源：`meta-diagnosis-sop.md` / `meta-diagnosis-layers-l0-l4.md` / `meta-operator-daily-workflow.md`；冲突见 `CONFLICTS.md`

### Q6. ROAS 突然崩了第一步做什么？
**A**：按速查表：ROAS 全面崩盘（<0.7x）→P0，先查 Pixel/归因和落地页是否正常**排除假崩盘**（归因漏报是概率第一根因），再逐层穿透；ROAS 崩但转化量正常→大概率归因问题（L0），查 EQ 与转化延迟，**勿动投放策略**。
> 溯源：`meta-diagnosis-layers-l0-l4.md`

### Q7. L0–L4 五层各管什么？先查哪层？
**A**：固定顺序 L0 账户健康（归因/事件/结构/埋点/预算/合规 6 项）→ L1 Campaign（Pacing/出价/学习/CBO/频控/整体效能 6 项）→ L2 AdSet（受众效率/规模/LAL/重叠/版位 5 项）→ L3 素材（CTR/视频/疲劳/文案/CAT 5 项）→ L4 落地页六层漏斗（6 项）。每层最后一项是综合判定决定是否下钻；**L0 任一 P0 未清前，后面所有诊断结论无效**。每个诊断项统一六段式 SOP（前置准备→详细步骤→数据记录→异常处理→结果判定→后续动作），共 28 项可直接转 Agent 工具调用。
> 溯源：`meta-diagnosis-layers-l0-l4.md` / `meta-diagnosis-sop-agent-training.md`

### Q8. 怎么区分「受众问题」和「素材问题」？
**A**：交叉验证法（L2-01/I-2）：把 Bottom AdSet 的素材与 Top AdSet 用的同套素材对比——同素材在 A 受众差、B 受众好→受众问题（关停/单独降价 30%）；该素材在所有受众都差→素材问题（移交 L3）。要求近 14 天数据、样本≥50 转化、排除学习期；结论必须明确写「受众差 or 素材差」，不许写模糊的「都需优化」。
> 溯源：`meta-diagnosis-layers-l0-l4.md` / `meta-operator-daily-workflow.md`

### Q9. Learning 期能做优化动作吗？
**A**：不能。周转化<50 属学习中，只看趋势+记学习进度，不做任何动作；Learning 7 天+ 未脱离才介入（合并重复受众/扩受众/合并低预算 AdSet/停频繁编辑）；频繁掉回 Learning→冻结 2 周不做改动。L1-03：20~50 学习中、<20 样本不足；每次编辑重置学习，故 B-8 同样禁止动预算。
> 溯源：`meta-operator-daily-workflow.md` / `meta-diagnosis-layers-l0-l4.md`

### Q10. 素材什么时候换？怎么给创意团队提需求？
**A**：C-1/I-1：素材 CTR<0.5% 或周环比-30%+（疲劳）即列「需替换」。需求单四要素：替换对象（素材/上线天数/CTR）、失败原因（视觉/首屏/文案/疲劳）、新方向建议（人群×场景×卖点，不要同主题微调）、交付时间 48h。素材库周净增<3 条新方向→预警创意产能。
> 溯源：`meta-operator-daily-workflow.md` / `meta-diagnosis-layers-l0-l4.md`

### Q11. 新素材上线后多久能判？素材疲劳怎么识别？
**A**：保护期——上线 <3 天或点击 <50 不做判定不做删除（S6 口径；S7 另有「学习期不判效」）。疲劳信号多口径并存：S6/S7 用 CTR<0.5% 或周环比-30%+（I-1.5 佐证频次>4）；S4 sheet-02 用素材疲劳比=当前 CTR÷历史峰值 CTR，≥0.70 正常、<0.70 且频次≥3 异常；S7 L3-03 用上线>14 天重点查、CTR 周环比-30%+=预警、频次>4 且 CTR 跌=确认疲劳。处置：48h 内上新替代（同主题新画面/新 hook，非微调），疲劳素材降权或关闭但可留作受众验证。
> 溯源：`meta-operator-daily-workflow.md` / `meta-diagnosis-metrics.md` / `meta-diagnosis-layers-l0-l4.md`；冲突见 `CONFLICTS.md`

### Q12. 落地页 CVR 低怎么定位断在哪一层？
**A**：I-3 六层漏斗找「断崖式下降」：曝光→点击（出站CTR≥1%）→ 到达（LPV/出站点击≥70%）→ 浏览（VC/LPV≥60-70%）→ 加购（ATC/VC 3-8%）→ 结账（IC/ATC≥60%）→ 购买（Purchase/IC≥70%，ATC→P≥30%）+ 归因兜底（差≤20%）。注意 S8 模板用「访客数（当日末次归因）」四段漏斗（加购→添加订单→到达结账→完成结账），与 S7 事件数五段口径不同 `[待确认]`。数据门槛见 Q5；断点在「点击→到达」<60% 按技术问题修复后 48h 复测。
> 溯源：`meta-operator-daily-workflow.md` / `meta-diagnosis-layers-l0-l4.md` / `meta-post-launch-data-inspection.md`；冲突见 `CONFLICTS.md`

### Q13. 动作做完多久验证？不达预期怎么办？
**A**：验证窗口 48h（素材）/72h（动作）/7d（结构调整）。R-1 回看：实际指标达成预期 ±15% →「有效，固化」可放量；未达成 →「无效，回滚或换动作」并记录根因（误诊？执行错？外部变化？）；样本<50/大促期 → 延长观察 48h 不下结论。归因/像素类 P0 修复后 48h 复测。达到回滚条件（CPA+≥20% 或 ROAS-≥20% 或数据延迟>6h）→ 自动/人工回滚最近动作+记录原因+重新进入前置检查+升级 P0 告警；预警档（CPA+10~20%/ROAS-10~20%）只密切监控、禁止追加动作。
> 溯源：`meta-operator-daily-workflow.md` / `meta-action-library.md`

### Q14. 动作库一共有多少动作？都是什么类型？
**A**：16 个（A-01~A-16）：继续观察、预算增/减（20%/50%）、暂停劣质组/广告、调整受众、加排除名单、调出价、换补素材、重剪视频前3秒、设频次上限、关劣质版位、优化落地页、简化结账、结构重构、修复归因/像素。注意 S7 决策树出口的 A-xx 编号与 S4 A-01~A-16 **无法逐一对应**（如 T1.4「扩预算20%(A-03)」在 S4 中 A-03 是 +50%），S7 动作库 18 行语义上与 S4 高度重叠但编号体系不同 `[待确认]`。
> 溯源：`meta-action-library.md` / `meta-diagnosis-sop-agent-training.md`；冲突见 `CONFLICTS.md`

### Q15. 动作预估幅度可以当承诺吗？
**A**：不能。原文声明是「DTC 中高客单商品初始经验值」（客单 $100-300），需按国家、目标、季节、客单价和账户历史校准，±50% 浮动、大促放大 1.5-2x；且每个动作都有验证窗口和回滚条件，未达预期即回滚。
> 溯源：`meta-action-library.md`

### Q16. 扩量预算怎么操作才安全？P0 止血用什么动作？
**A**：扩量：A-02 预算增加 20% 需 ROAS≥目标1.3倍、CPA≤目标0.8倍且学习完成，单次不超 30%、分 2~3 次扩量，48 小时/次复核，回滚线 CPA+20% 或 ROAS-20%；更大扩量用 A-03（+50%）分 3 次、预留学习期、验证 7 天。止血：A-04 预算缩减 20%~50%（适用 CPA>目标1.5倍连续3天）止血后必须继续找根因；或 A-05 暂停劣质广告组/广告（需 CPA≥系列均值2倍且交叉验证确认）。ROAS<盈亏平衡×0.7 时走「暂停系列→查 CPA/客单价/归因口径」止血路径。
> 溯源：`meta-action-library.md`

### Q17. 为什么动作日志必须 21 列全填？
**A**：铁律「动作必留痕」——每行=一个动作，72h 后回填实际结果与复盘备注，是新人成长的唯一路径，也是 R 环节（S6）72h 回看的数据源。前 9 列对应五段式诊断输出（异常/证据/根因），10~15 列登记动作与执行人，中间 3 列是 4h/24h/72h 复核回填，末 3 列管回滚条件、状态与复盘——缺复核的动作视为未闭环。
> 溯源：`meta-action-library.md`

### Q18. 什么时候只「继续观察」（A-01）？
**A**：指标偏离 ±15% 以内、学习期内、样本不足或大盘萎缩时。前提：学习期不足 50 次转化不强动作；验证窗口 3 天；若出现 P0 数据或资格异常则转修复。
> 溯源：`meta-action-library.md`

### Q19. A-16 修复归因/像素算投放动作吗？A-15 结构重构为什么中高风险？
**A**：A-16 不算投放类动作，是数据修复动作——适用 EQ<4、转化漏报、数据不一致；预估影响是「不预估投放提升，但恢复判断基础」，修复后等 48 小时稳定再复测（EQ 仍<4 或重复>30% 视为失败）。A-15 结构重构风险标「中高」因它会重置学习状态、短期波动约 -10%，仅适合 Learning Limited 多、结构混杂、测试/收割混跑的场景；要求低活跃期执行、完成后 14 天不反复，回滚线为学习状态恶化。
> 溯源：`meta-action-library.md`

### Q20. 诊断指标一共有多少个？阈值都是固定值吗？
**A**：sheet-02 实际 26 行指标（S5 PRD 口径称 25 项基准线，差 1 项待确认）。阈值不是固定值——sheet-02 明确为「第一版可配置默认值」，需按国家、目标、版位、设备、新客/重定向、行业和季节校准；sheet-01 节点行内 IF 条件自带阈值，两表口径存在差异，落地以节点阈值为准。
> 溯源：`meta-diagnosis-metrics.md`

### Q21. CPA/ROAS 在什么条件下才能正常判断？CTR/CPC/CPM 健康区间？
**A**：CPA/ROAS 两个前提——归因窗口成熟度 ≥80%（未成熟仅预警、禁止判断）；购买样本 ≥10 且统计口径为「购买≥10且成熟」。CPA 目标值按毛利/AOV 推导，ROAS 目标按贡献毛利推导。CTR 按目标分：销售≥0.8%、引流≥1.0%（异常：销售<0.5%、引流<0.7%）。CPC ≤$1.20 初始值、>$2 严重（按国家调整）。CPM $8~$25 参考、较基准 +30% 预警（需同期比较）。落地页漏斗基准：LPV达到率≥70%、页面加载<3秒、浏览率≥60-70%、加购率≥3%冷流量/≥10%重定向、到达结账率≥60%、完成结账率≥70%。
> 溯源：`meta-diagnosis-metrics.md`

### Q22. 素材疲劳比怎么算？频次多少算过高？视频素材专属指标？
**A**：疲劳比=当前 CTR÷素材历史峰值 CTR，成熟素材 ≥0.70 正常，<0.70 且频次≥3 异常；新素材不判疲劳（sheet-01 S1-04a 另加质量排名=Below Average 条件）。频次口径四档并存：sheet-02 ≤5 正常（重定向≤6）、>5 且 CTR 下滑预警、>10 严重；sheet-01 S2-08 更严 ≤3 且重叠≤20%；S7 L3-03 频次>4 且 CTR 跌=确认疲劳。视频指标两套阈值并存：3秒播放率 sheet-02 ≥25%/<15% vs sheet-01 ≥30%/<25%；完播率 sheet-02 ≥8%/<4% vs sheet-01 ≥10%(15s)/<5%，均「按时长校准」。异常方向部分双向（Pacing <60%/>130%、出价达成率 >1.5/<0.7 连续3天、CPM +30%）。
> 溯源：`meta-diagnosis-metrics.md`；冲突见 `CONFLICTS.md`

### Q23. 哪些指标是「只观察不动作」的？异常速查第一步？
**A**：只观察类：报表延迟 3~6 小时、预警档指标（如 CPM $25~30、CTR 0.5~0.8% 多为「持续观察/储备素材」）、样本不足（Purchase<10）仅监控。异常速查：ROAS 全面崩盘（<0.7x）→P0 先排归因假崩盘；归因/事件异常→P0 修复；账户受限/落地页不可达→P0；Pacing 异常→预算节奏分支。
> 溯源：`meta-diagnosis-metrics.md` / `meta-diagnosis-layers-l0-l4.md`

### Q24. S7（Agent 训练版）和 S4（产品策略树）什么关系？阈值冲突听谁的？
**A**：同源异构：S7 按 L0–L4 五层+T0–T5 决策树组织带完整六段式 SOP 步骤，是 Agent 训练版；S4 按 G0–G8 阶段+65 节点/196 分支组织，是产品化规则资产；S5 PRD 在 S4 之上做产品化。典型冲突：L4 数据门槛 S7=$50/14天 vs S4=$100+Purchase≥50；素材疲劳 S7=周环比-30% vs S4=CTR/峰值<0.70（指标定义不同）；3秒播放/完播率两套数值；EQ 阈值 S6 排雷 EQ<6 vs S7/S4 EQ<4。**执行级判定建议以 S4 节点 IF 条件为准，S7 作为业务语义与 SOP 步骤来源** `[推断]`。S7 和 S4 哪个更新无法从导出内容判断 `[待确认]`。
> 溯源：`meta-diagnosis-sop-agent-training.md` / `meta-diagnosis-layers-l0-l4.md`；冲突见 `CONFLICTS.md`

### Q25. 投放师的一天按什么顺序做事？能跳环节吗？
**A**：09:00 晨会 M → 09:30–10:30 W 监控 → 10:30–12:00 I 排查 → 13:00–14:30 B 预算 → 14:30–16:00 C 素材 → 16:00–17:00 R 复盘 → 17:00–17:40 D 日报 → 17:40–18:00 P 规划。主干口诀「排雷→监控→穿透→动作」；**任何环节开始前先做账户级 15 秒排雷**（EQ<6 / 账户受限 / 归因差>30% 任一命中即 P0 收口），命中 P0 时该对象今日不做任何投放判断。禁动预算三条：根因是素材问题、Learning 未满 50 转化、W 层只标记不砍预算须进 I 穿透。
> 溯源：`meta-operator-daily-workflow.md`

### Q26. 日报必须包含什么？有什么纪律？
**A**：五段式——①今日概览（花费/GMV/ROAS vs 目标，偏差>15% 标红）②异常与根因（层级+字段+证据值+根因）③今日动作（类型+对象+预期+验证窗，引用日志编号）④结果回看（72h 前动作达成情况）⑤明日重点（P0/P1+待回看项+排期提醒）。纪律：每条结论带证据值、所有动作引用动作日志编号、异常必须先排归因再下结论。
> 溯源：`meta-operator-daily-workflow.md`

### Q27. Meta 投后巡检采集哪些数据？模板怎么设计？
**A**：按三层级采集：Campaign 层（预算/出价/状态 + 曝光 CPM/频次/份额 + 点击 CTR/CPC + LPV 漏斗五段 + CVR/CPA/GMV/ROAS）、AdSet 层（加人群包/排除包/版位）、Ad 层（加素材形式/素材ID/文案/CAT/Adv+ Creative 开关），报表窗口 14 天。每层 sheet 尾部两个列块：「巡检结论」=巡检日期/诊断结论(异常+证据值)/推荐动作/改动明细/预期影响/优先级/再次巡检重点；「运营操作记录」=执行时间/诊断更新/实际动作/改动明细/预期影响/复检重点。一行=一个实体的指标+诊断+回填一体化台账。案例：吸奶器X1 Q4 上市项目 14 天窗口（2026-09-03~16）3 个 Campaign 分别做 Hook 素材实验（ROAS 2.02）、出价策略实验（Traffic/Lowest cost）、再营销人群实验（Leads/ROAS）。模板标题「待业务确认」，字段口径仍在评审。
> 溯源：`meta-post-launch-data-inspection.md`

### Q28. 这套诊断 SOP 适用什么场景？S6 和规则资产版什么关系？
**A**：适用 Meta（Facebook/Instagram/AN）广告，DTC 母婴/消费品为主（阈值为 DTC 中高客单 $100-300 经验值，实际±50% 浮动、大促放大 1.5-2x）；案例账户 Momcozy（US-Pump-M5、US-Wearable-M9）；可扩展 TikTok/Google 但需重新校准阈值；目标以销售/DTC 为主兼容引流/线索/应用安装等 8 类。S6 是人类执行版（按一天时间×环节组织，告诉投放师现在该停在哪）；S4/S5/S7 是规则资产版（按 G0–G8×65 节点或 T0–T5+L0–L4 组织，告诉 Agent 异常对象怎么穿透定位根因）；两者阈值大体同源，S6 的 P0 修复引用 S7 的 L0/L4 节点编号；对 Agent 而言 S6 提供日节奏编排与动作白名单的人类基准 `[推断]`。
> 溯源：`meta-diagnosis-sop.md` / `meta-diagnosis-sop-agent-training.md` / `meta-operator-daily-workflow.md`

### Q29. 多渠道广告日报/周报/月报的标准结构是什么？
**A**：三段式——①大盘纵览（Shopify 总销售额+总广告消耗→大盘 ROAS≈销售额÷消耗，趋势方向+关键节点）②渠道拆解（每渠道 spend/ROAS/orders 表格 + 增长引擎 vs 拖后腿二分 + cross-channel 对比）③行动指令（≥3~5 条量化建议：渠道名+加减预算 %/金额+关停/放量方式）。报告类型分单日快照/日期区间/周末三日汇总/Week 汇总行/月报五种口径，各自有对应解读要求。
> 溯源：`multi-channel-report-contract.md`

### Q30. 什么是「大盘 ROAS」？和渠道 ROAS 什么关系？
**A**：大盘 ROAS ≈ Shopify 总销售额 ÷ 全渠道总广告消耗（MER 朴素口径），衡量整体投入产出比与业务体量；渠道 ROAS 是单渠道口径。报告第一章用大盘 ROAS 评估整体，第二章用渠道 ROAS 排序找增长引擎（消耗增长且 ROAS 健康）vs 拖后腿（ROAS 偏低/消耗虚高/转化下滑）。跨源口径不一致时以 Shopify 行内 `Ad Spent_<渠道>` 列为准。
> 溯源：`multi-channel-report-contract.md`

### Q31. AI 生成的广告报告怎么防止「正确的废话」？
**A**：四条硬纪律——所有结论必须引用具体数字（消耗/ROAS/销售额/订单数），禁止空泛描述；禁止「持续观察」「进一步优化」类表述；行动指令每条必须含渠道名+量化幅度（+20%/-500 USD/暂停 XX 广告组）；渠道无数据时注明「该渠道此区间无数据」而非编造。另有工程分工防线：数据表格由代码确定性生成，LLM 只写洞察文字（分节模式三次调用各写一章，单章 temperature ≤0.4 防截断）。
> 溯源：`multi-channel-report-contract.md`

### Q32. 同一品牌为什么拆多个 Meta 广告账户？报告里怎么处理？
**A**：品牌矩阵/品线分投场景常见（meta-ad-analysis 案例：WearNuage/NuageBra/Nuage2026/NuageWear 四个账户 Sheet）。报告按账户维度各自拆解再 cross-channel 对比；已停投账户自动跳过不纳入当期分析。
> 溯源：`multi-channel-report-contract.md`

### Q33. AppLovin 在多渠道广告报告里算什么角色？
**A**：效果广告渠道之一（案例中以 Axon 名义出现），与 Google/Meta 并列做 spend/ROAS/orders 对比，纳入增长引擎/拖后腿二分。KB 中 AppLovin 方法论目前空白，本批仅登记平台实体与报告口径 `[待确认]`。
> 溯源：`multi-channel-report-contract.md`

### Q34. 多渠道报告契约和投放师一日工作流 SOP 什么关系？
**A**：互补不冲突——S6 管单渠道 Meta 的日内操作节奏与动作铁律（回答「今天做什么」）；本契约管多渠道周期报告的输出结构与量化纪律（回答「这周期整体怎么样、预算往哪调」）。S6 的五段式日报偏「今日动作闭环」，本卡三段式偏「跨渠道体量判断+预算指令」；两者可在 Agent 编排中串联（日内操作→周期报告）。
> 溯源：`multi-channel-report-contract.md` / `meta-operator-daily-workflow.md`
